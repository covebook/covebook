## 0. 한 장 요약

- 결제 방식: 스토어 인앱결제만. PG 계약 없음. 서버는 기존 Go 서버
- 상품: 구독 1종(월·연) + 추가 선반(한 번 사면 영구)
- 한국은 2025~2026년에 구독 규제가 크게 강화됨. 화면과 고지를 잘못 만들면 과태료·영업정지 대상
- 그래서 결제 기능과 함께 구독 관리, 구매 내역, 사업자 정보, 알림함을 만들어야 함
- 알림은 앱 안에서 해결. 서버 푸시, 이메일, 카카오 알림톡은 지금 만들지 않음
- 가격은 출시 뒤 올리기 어려움. 올리려면 구독자마다 별도 동의가 필요
- 해외 결제 확장에 대비해 결제 경로, 통화, 나라별 규칙을 값으로 둠
- 작업은 main에 바로 올리지 않고 이슈·PR로. 마일스톤 "인앱결제 1차", 이슈 #6~#18
- 정환이 정해 줄 것 8가지 (8장)
- 가장 먼저 시작할 것: 사업자등록과 스토어 준비. 코드와 무관하게 오래 걸림

## 1. 무엇을 파나

- 구독 1종(월·연): 선반·벽지색 유료 버전, 투명 선반 위젯, ASMR 추가분
- 추가 선반: 한 번 사면 영구
- 코인(재화) 방식은 안 씀
- 결제는 스토어 인앱결제만. PG를 같이 붙여도 수수료 이득이 거의 없음
- 가격, 수수료 계산, 실수령액은 저장소에 올리지 않음. 파일로 따로 공유

| 날짜 | 일 |
|---|---|

| 2025-10-15 | 구독 플랫폼에 첫 과태료 (중도해지 안내 미흡) |

| 2026-11-06~26 | 소비자보호 지침 개정안 행정예고. 탈퇴·해지 방해 기준 구체화 |

### 2-2. 위반하면

- 과태료: 1차 100만 원, 2차 200만 원, 3차 이상 500만 원
- 영업정지: 1차 3개월, 2차 6개월, 3차 12개월. 과징금으로 대신할 수 있음
- 광고성 알림 규칙 위반(정보통신망법): 3천만 원 이하 과태료
- 스토어 심사 반려: 표시 누락, 구매 복원 없음, 계정 삭제 없음

### 2-3. 우리에게 걸리는 규칙

| 규칙 | 내용 | 우리 대응 |
|---|---|---|
| 숨은 갱신 금지 | 가격 인상, 무료→유료 전환은 그 전 30일 이내에 별도 동의 | 가격 인상 안 함. 무료 체험 안 함 |
| 해지 방해 금지 | 해지를 가입보다 복잡하게 하면 위반. 앱 서비스의 해지를 PC·웹으로만 받는 것도 위반 사례 | 설정 첫 화면에서 한 번에 닿는 "구독 관리" |
| 가격 숨기기 금지 | 처음 보여 준 가격과 최종 가격이 같아야 함. 부가세 포함 | 결제 화면에 가격·주기·갱신을 모두 표시 |
| 미리 선택 금지 | 옵션을 미리 선택해 두면 위반 | 요금제를 미리 선택해 두지 않음 |
| 반복 팝업 금지 | 거절한 사람에게 다시 띄우면 위반 | 구독 권유는 거절하면 다시 안 띄움 |
| 탈퇴 방해 금지 | 탈퇴 버튼을 찾기 어려운 곳에 두거나 설문·본인인증을 끼우면 위반 | 탈퇴도 설정 첫 화면에서 한 번에 |
| 사업자 정보 표시 | 상호, 대표자, 주소, 전화번호, 전자우편주소, 사업자번호, 통신판매업 신고번호 | 설정에 화면 추가. 전화번호 준비 필요 |
| 거래기록 열람 | 유저가 자기 거래기록을 보고 저장할 수 있어야 함 | 구매 내역 화면 |
| 기록 보존 | 계약·결제 기록 5년, 불만·분쟁 기록 3년 | 탈퇴해도 분리 보관 |
| 약관 명시 | 결제·해지·환불 정책과 문의 방법 | 약관 개정 |
| 광고 알림 | 수신 동의, 야간 별도 동의, 2년마다 재확인, `(광고)` 표기 | 광고 알림을 보내지 않음. 거래 고지에 홍보 문구를 넣지 않음 |

### 2-4. "정기결제 알림을 안 보내면 벌금"이라는 말

- 의무로 확인된 것: 가격 인상과 무료→유료 전환 때의 사전 동의·고지. 약관에 미리 적어 둔 것, "거부 안 하면 동의"는 인정되지 않음
- 의무로 확인되지 않은 것: 가격이 그대로인 일반 갱신 전 알림
- 방향은 의무화 쪽
  - 방미통위 안내서(2026-05-27)가 자동결제 전 사전 안내를 권고
  - 국민권익위 권고로 문체부가 콘텐츠이용자보호지침 개정 추진
  - 미국 캘리포니아는 이미 의무, 영국은 2027년 봄 시행 예정
- 확인이 필요한 주장: "갱신일 14일 전까지 이메일·문자로 개별 통지가 의무"라고 적은 법률 칼럼이 하나 있음. 정부 자료에서는 확인되지 않음. 사실이면 연락처 수집이 필수가 됨
- 결정: 연 구독은 갱신 전에 알림. 한국 초기값 14일 전. 값은 나라별 표로 관리

### 2-5. 스토어가 해 주는 것과 우리가 할 것

| 일 | 스토어 | 우리 |
|---|---|---|
| 결제 시트의 금액 표시 | 함 | 그 전 화면에 같은 내용 표시 |
| 한국 유료 전환 동의 수집 | 애플은 함. 구글은 확인 못 함 | 체험을 도입할 때만 해당 |
| 가격 인상 동의 | 애플은 한국을 "동의 필요"로 분류 | 인상 계획, 고지, 동의 기록 |
| 환불 결정·지급 | 함 | 권한 회수, 유저 안내, 문의 대응 |
| 해지 처리 | 함 | 앱 안에서 해지 경로 안내 |
| 약관, 사업자 정보, 기록 보존, 구매 내역 | 안 함 | 함 |

### 3-5. 알림 채널

| 채널 | 결론 | 이유 |
|---|---|---|
| 앱 안 알림함·화면 | 필수 | 지금 유저에게 닿는 유일한 확실한 수단 |
| 기기 예약 알림 | 권장 | 서버 푸시 없이 갱신 전 알림 가능 |
| 서버 푸시 | 보류 | 지금 의무 없음. 설정, 토큰 저장, 발송 서버가 필요 |
| 이메일 | 보류 | 주소는 로그인 계정에 있지만 용도가 계정 표시뿐. 고지에 쓰려면 처리방침 개정과 발송 서비스 |
| 카카오 알림톡 | 안 함 | 전화번호 수집, 사업자·딜러사 계약, 템플릿 심사, 건당 비용 |

- 가격 인상·유료 전환 동의는 통지 수단을 정한 조항을 찾지 못함. 요건이 "별도의 명시적 동의"라 앱 안 동의 화면이 가장 확실. 푸시만으로는 동의를 받을 수 없음
- 서버 푸시·이메일이 필요해지는 때: 가격 인상, 무료 체험 도입, 개별 통지 의무 확인, 광고 알림, 해외 판매
- 대비: 알림 코드를 채널 인터페이스 뒤에 둠. 나중에 구현만 추가
- 알림톡: 2026-11-01 심사 기준 변경으로 갱신 유도 문구는 발송 불가. 결제 예정 금액·결제일 같은 사실 안내만 가능
- 거래 고지에 홍보 문장을 넣으면 광고성 정보가 됨. 수신 동의, `(광고)` 표기, 야간 동의, 2년 재확인, 수신거부 바로가기가 전부 필요해짐

## 4. 설계

### 4-1. 구조

- 앱(Flutter)이 스토어에서 결제 → 거래를 서버에 제출 → 서버가 스토어에 다시 조회 → 지급
- 스토어 알림(환불, 갱신, 만료)도 서버가 받아 다시 조회한 뒤 반영
- 하루 1회 대조로 놓친 알림을 메움
- 권한(구독 여부, 선반 칸 수)의 기준은 서버 DB. 앱은 받아서 캐시

### 4-2. 언어와 라이브러리

- Go 서버 유지. 결제만 다른 언어로 쪼개지 않음
- 애플은 Go용 공식 라이브러리가 없음. 오픈소스 `awa/go-iap` 사용
  - 별 1,062, 의존하는 공개 저장소 195개. Go에서는 사실상 표준
  - 보안 문제는 지금까지 1건. 가짜 영수증이 통과하던 문제였고 v1.59.1에서 수정
- 대응: v1.59.1 이상만 사용. 영수증을 믿지 않고 스토어 재조회 뒤 지급
- 서명 검증은 직접 짜지 않음. 우리가 짜는 것은 재조회, 값 비교, 중복 방지, 계정 확인

### 4-3. 문제가 나면 피해 범위

- 돈과 카드 정보는 스토어가 쥐고 있음. 위조로 돈이 빠져나가지는 않음
- 위조로 가능한 것: 무료 이용, 가짜 환불 알림으로 남의 구독 끊기
- 가장 위험한 것: 서버에 넣는 스토어 키 유출. 구글 키로는 환불 API를 부를 수 있음
- 대응: 키는 최소 권한만. 알림 주소는 서명 검증을 통과한 것만 재조회

### 4-4. 주요 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 추가 선반 유형 | 소모성. 한 번 사면 영구, 계정에 기록 | 1칸·3칸을 여러 번 살 수 있어야 함. 비소모성은 두 번 못 삼 |
| 구독 구조 | 권한 하나. 월·연이 같은 권한 | 전환은 스토어가 처리 |
| 계정 여럿 | 구독은 "복원"을 누른 계정으로 이전 | 앱을 다시 깔면 기기 계정이 바뀜 |
| 비로그인 구매 | 허용, 로그인 권유 | 가입 강제는 애플 심사 반려 사례가 있음 |
| 지급 순서 | DB 저장 → 스토어 확인 → 앱이 거래 종료 | 구글은 3일 안에 확인하지 않으면 자동 환불 |
| 검증 전 지급 | 안 함. "구매 확인 중" 표시 | 먼저 열면 위조도 열림 |
| 결제 실패 | 유예 기간에는 유지, 그 뒤 해제 | 애플 유예 기간은 직접 켜야 함 |
| 구독 만료 | 아무것도 안 지움. 유료 꾸미기만 기본값으로 표시 | 유저 기록 보호 |
| 환불된 선반 | 잠금, 책은 유지 | 유저 기록 보호 |
| 무료 체험 | 없음 | 유료 전환 동의 대상이 됨. 처리도 복잡해짐 |

- 선반을 소모성으로 하면 스토어의 구매 복원으로는 선반이 안 돌아옴. 계정이 유일한 기록
- 애플 심사가 소모성 선반을 반려하면 비소모성으로 전환

### 4-5. 해외 결제 대비

- "해외 결제"는 해외 스토어 판매일 수도, 스토어 밖 결제수단일 수도 있음. 둘 다 대비
- 결제 경로를 값으로 저장. 지금은 `apple`, `google`. 나중에 값과 구현만 추가
- 통화, 금액, 판매 국가를 거래마다 저장
- 가격은 스토어가 주는 현지 가격을 표시. 앱에 숫자를 적지 않음
- 고지 규칙(무엇을, 며칠 전에)을 나라별 표로 관리
- 시각은 UTC
- 감수하는 것: 지금 안 쓰는 칸을 미리 만듦. 대신 해외 결제 때 테이블을 안 고침

## 8. 정환이 정해 줄 것

1. 추가 선반 "최대 3칸"의 범위: 연도 책장마다 / 계정 전체. 테이블이 달라짐
2. 가격 확정. 출시 뒤에는 올리기 어려움
3. 무료 체험 없이 출시하는 것
4. 잠긴 선반의 책을 다른 선반으로 옮기게 할지
5. "해외 결제"의 범위: 해외 스토어 판매 / 스토어 밖 결제수단
6. 사업자등록 명의와 시기, 대표 전화번호
7. 로그인 이메일을 결제 고지에도 쓸지. 주소는 이미 저장하지만 용도가 계정 표시뿐이라 처리방침을 고쳐야 함
8. 세무·법률 확인을 맡길 곳

## 9. 전문가에게 확인할 것

- "갱신일 14일 전까지 개별 통지"가 실제 의무인지. 1순위
- 스토어 결제에서 우리가 전자상거래법상 통신판매업자인지
- 동의 시점: 정부 자료는 "증액·전환 전 30일 이내", 애플 공지는 "결제·전환일로부터 30일 이내"
- 디지털 상품의 청약철회 제한을 적용하려면 필요한 조치
- 거래 고지와 광고성 정보를 나누는 기준
- 기록 보존 기간의 현행 조문
- 만 14세 미만의 가입·결제. 지금 가입 흐름에 나이 확인이 없음
- 사업자 전화번호를 개인 번호로 써도 되는지
- 간이과세자의 통신판매업 신고 면제 여부
- 해외 판매분의 세금 신고 범위

- 구글의 한국 동의 절차, 계정 삭제 요건은 확인 못 함

- 셰이더 생성 스크립트와 `flutter test`는 돌려 보지 못함. 작업 환경에 Flutter 없음
