## 0. 한 장 요약

- 결제는 스토어 인앱결제로만. 서버는 기존 Go 서버
- 한국은 2025~2026년에 구독 규제가 크게 강화됨. 화면과 고지를 잘못 만들면 과태료·영업정지 대상
- 그래서 결제 기능과 함께 "고지·동의·해지" 기능을 같이 만듦
- 해외 결제 확장을 대비해 결제 경로, 통화, 나라별 규칙을 값으로 둠
- 작업은 main에 바로 올리지 않고 이슈·PR로. 마일스톤 "인앱결제 1차"
- 정환이 정해 줄 것 6가지 (6장)

## 1. 법규에서 꼭 알아야 할 것

### 1-1. 최근 흐름

| 날짜 | 일 |
|---|---|
| 2025-02-14 | 전자상거래법 다크패턴 규제 시행. 금지 유형 6개 |
| 2025-10-15 | 구독 플랫폼에 첫 과태료 (중도해지 안내 미흡) |
| 2026-10-06 | 공정위가 13개 유형 가이드라인 배포 |
| 2026-11-06~26 | 소비자보호 지침 개정안 행정예고. 탈퇴·해지 방해 기준 구체화 |

### 1-2. 위반하면

- 과태료: 1차 100만 원, 2차 200만 원, 3차 이상 500만 원
- 영업정지: 1차 3개월, 2차 6개월, 3차 12개월 (또는 과징금)
- 광고성 알림 규칙 위반(정보통신망법): 3천만 원 이하 과태료

### 1-3. 우리에게 걸리는 규칙

| 규칙 | 내용 | 우리 대응 |
|---|---|---|
| 숨은 갱신 금지 | 가격 인상, 무료→유료 전환은 그 전 30일 이내에 별도 동의 | 가격 인상 안 함. 무료 체험 안 함 |
| 해지 방해 금지 | 해지를 가입보다 복잡하게 하면 위반 | 설정 첫 화면에서 한 번에 닿는 "구독 관리" |
| 가격 숨기기 금지 | 처음 보여 준 가격과 최종 가격이 같아야 함 | 결제 화면에 가격·주기·갱신을 모두 표시 |
| 미리 선택 금지 | 옵션을 미리 선택해 두면 위반 | 요금제를 미리 선택해 두지 않음 |
| 반복 팝업 금지 | 거절한 사람에게 다시 띄우면 위반 | 구독 권유는 거절하면 다시 안 띄움 |
| 약관 명시 | 결제·해지·환불 정책과 문의 방법 | 약관 개정 |
| 사업자 정보 표시 | 상호, 사업자번호, 통신판매업 신고번호 | 설정 화면에 표시 |
| 기록 보존 | 결제·계약 기록 5년 | 탈퇴해도 분리 보관 |
| 광고 알림 | 수신 동의, 야간 별도 동의, 2년마다 재확인 | 거래 고지와 광고를 분리 |

### 1-4. "정기결제 알림을 안 보내면 벌금"에 대해

- 확인된 의무: **가격 인상**과 **무료→유료 전환** 때의 사전 동의·고지. 이건 위반 시 제재 대상
- 확인 안 된 것: 가격이 그대로인 **일반 갱신 전 알림**의 법적 의무. 검색에서 의무 조항을 찾지 못함
- 다만 방향은 의무화 쪽
  - 국민권익위 권고로 문체부가 콘텐츠이용자보호지침 개정 추진 (요금 변경 전 결제 예정 내역 사전 고지)
  - 정부 구독 서비스 개선방안에 사전 고지·동의 의무화 포함
  - 미국 캘리포니아, 영국은 갱신 알림이 이미 의무이거나 시행 예정
- 결정: 연 구독은 갱신 전에 알림을 보냄. 며칠 전인지는 나라별 표로 관리해 법이 바뀌면 값만 고침

### 1-5. 스토어가 해 주는 것과 우리가 할 것

| 일 | 스토어 | 우리 |
|---|---|---|
| 결제 시트의 금액 표시 | O | 그 전 화면에 같은 내용 표시 |
| 한국 유료 전환 동의 수집 | 애플 O, 구글 미확인 | 체험을 도입할 때만 |
| 환불 결정·지급 | O | 권한 회수, 문의 대응 |
| 해지 처리 | O | 해지 경로 안내 |
| 약관, 사업자 정보, 기록 보존 | - | O |

## 2. 설계 요약

### 2-1. 구조

- 앱(Flutter)이 스토어에서 결제 → 거래를 서버에 제출 → 서버가 스토어에 다시 조회 → 지급
- 스토어 알림(환불, 갱신, 만료)도 서버가 받아 다시 조회 후 반영
- 하루 1회 대조로 놓친 알림을 메움
- 권한(`plus`, 선반 칸 수)의 기준은 서버 DB

### 2-2. 주요 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 추가 선반 | 소모성. 한 번 사면 영구, 계정에 기록 | 1칸·3칸을 여러 번 살 수 있어야 함 |
| 구독 | 권한 하나. 월·연 같은 권한 | 전환은 스토어가 처리 |
| 위조 방지 | 받은 영수증을 믿지 않고 스토어 재조회 | 라이브러리에 구멍이 나도 걸림 |
| 계정 여럿 | 구독은 "복원"한 계정으로 이전 | 앱을 다시 깔면 기기 계정이 바뀜 |
| 비로그인 구매 | 허용, 로그인 권유 | 가입 강제는 애플 심사 반려 사례 |
| 결제 실패 | 유예 기간에는 유지 | 스토어 권고 |
| 구독 만료 | 아무것도 안 지움 | 유저 기록 보호 |
| 환불된 선반 | 잠금, 책은 유지 | 유저 기록 보호 |

### 2-3. 해외 결제 대비

- 결제 경로를 값으로 저장 (`apple`, `google`, 나중에 다른 값)
- 통화, 금액, 판매 국가를 거래마다 저장
- 가격은 스토어가 주는 현지 가격을 표시. 앱에 숫자를 적지 않음
- 고지 규칙(무엇을, 며칠 전에)을 나라별 표로 관리
- 문구 템플릿은 언어판을 추가하는 방식

### 2-4. 해외 규칙 한눈에

| 지역 | 핵심 | 상태 |
|---|---|---|
| EU | 계약 철회 버튼 | 2026-06-19 적용 |
| 독일 | 해지 버튼 | 시행 중 |
| 미국 연방 | 클릭으로 해지 규칙 | 2025-07 무효, 재추진 중 |
| 미국 캘리포니아 | 갱신 알림, 동의 증빙 3년 | 2025-07-01 시행 |
| 영국 | 갱신 알림, 숙려 기간 | 2027년 봄 예정 |
| 일본 | 최종 확인 화면 | 시행 중 |

- 공통점: 표시, 명시적 동의, 쉬운 해지, 갱신 알림. 한국 대응과 같은 기능으로 대부분 해결

## 4. 진행 방식

- 결제 변경은 main에 바로 올리지 않음. 이슈 하나에 브랜치 하나, PR 하나
- 결제 화면은 빌드 플래그로 꺼 둔 채 머지 (main 푸시마다 TestFlight가 돌기 때문)
- 가격, 사업자 정보, 스토어 키는 저장소·이슈·PR에 적지 않음 (공개 저장소)
- 이슈·PR 양식을 추가함 (`.github/`)

## 6. 정환이 정해 줄 것

1. 추가 선반 "최대 3칸"의 범위: 연도 책장마다 / 계정 전체
2. 가격 확정. **출시 뒤에는 올리기 어려움** (인상하려면 구독자마다 별도 동의)
3. 무료 체험 없이 출시하는 것
4. 잠긴 선반의 책을 다른 선반으로 옮기게 할지
5. "해외 결제"의 범위: 해외 스토어 판매 / 스토어 밖 결제수단
6. 사업자등록 명의와 시기. 세무·법률 확인을 맡길 곳

## 7. 전문가에게 확인할 것

- 스토어 결제에서 우리가 전자상거래법상 통신판매업자인지
- 디지털 상품의 청약철회 제한을 적용하려면 필요한 조치
- 거래 고지와 광고성 정보를 나누는 기준
- 기록 보존 기간의 현행 조문
- 간이과세자의 통신판매업 신고 면제 여부
- 해외 판매분의 세금 신고 범위

## 8. 조사의 한계

- 법규는 정부 보도자료, 정책브리핑, 스토어 공식 문서로 확인한 것과 기사·로펌 자료로만 본 것이 섞여 있음. 구분은 ADR-0003 부록 A
- 2026-11 지침 개정안은 행정예고 중이라 확정 내용이 달라질 수 있음
- 국내 대형 서비스의 인앱결제 기술 글은 찾지 못함. 국내 사례는 개인 블로그 수준
- 샌드박스에서 직접 확인해야 하는 것이 남아 있음 (이슈 #15)
