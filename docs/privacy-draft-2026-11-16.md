# 개인정보 처리방침(웹 전문) 고칠 문구 초안 — 2026-11-16

웹 전문(노션, 앱 '처리방침 전문 보기(웹)')은 앱에서 고칠 수 없다. 페르소나 QA 2차(현우 F3)에서 앱 시트·웹 전문·실제 동작이 서로 달랐다. 아래는 실제 코드에 맞춘 고칠 문구다. 앱 안 시트(`flutter/lib/features/settings/settings_screen.dart` `_privacySheet`)는 같은 내용으로 이미 고쳤다.

## 실제 동작(코드로 확인)

| 항목 | 실제 동작 | 근거 |
|---|---|---|
| 저장 위치 | 책·독서 기록·갈피·감상·장정·책장 배치·설정·사진은 기기 안에 저장. 서버 주소(SYNC_URL)를 넣은 빌드만 서버에 동기화 | `services/sync.dart` `available` |
| 책 검색 | 검색어 → 책장 한켠 서버(`/books/search`, 서버가 YES24를 부름) → 서버에 닿지 않거나 결과가 없으면 Google Books → 그래도 없으면 Open Library | `services/book_search.dart` `searchBooks` |
| 인기 많은 책 | 책장 한켠 서버(`/books/popular`)에서 받음 | `popularBooks` |
| 상세 정보 | 고른 책이 Google Books·Open Library 결과면 그 서비스에 상세 요청 | `candidateDetails` |

| 글자 인식(갈피 사진) | 기기 안 ML Kit(Android)·Vision(iOS). 사진을 밖으로 보내지 않음 | `services/text_recognition.dart` |
| 바코드 | 기기 안 카메라 스캐너(ML Kit). 읽은 ISBN으로 위 검색 경로를 탐 | `features/book/barcode_scan_screen.dart` |
| AI 장정·사진으로 책 찾기 | 연결되지 않음(코드 없음) | — |
| 백업 파일 | 사용자가 만들 때만. Android는 다운로드/책장한켠에 바로 저장(고르는 창 없음)하거나 공유 창으로 보냄. iOS는 공유 창만. 직접 찍거나 고른 사진은 들어가고, 검색으로 받은 표지는 빠짐 | `store/backup.dart` |
| 공개 | 서버 없는 빌드: 공개되는 것 없음. 서버·커뮤니티가 열린 빌드: 사용자가 커뮤니티에 올린 글과 고른 항목만 공개. 같은 책(ISBN)의 공개 평가를 받을 때 ISBN이 서버로 감 | `services/community.dart`, `features/community/book_reviews.dart` |
| 계정 | 서버를 쓰는 빌드는 카카오·Apple·Google 로그인이 필수(2026-11-16). 로그아웃하면 이 폰의 기록을 지우고, 서버 계정 삭제도 있음 | `features/settings/backup_screen.dart` |

## 웹 전문에서 고칠 곳

1. **'기기에 저장하는 정보' 문단**
   - 지금: '…Covebook 서버(https://covebook.kodeploy.com)에에) 자동 동기화합니다. 서버 주소가 없는 빌드는…'
   - 문제: '에에' 겹침. '서버 주소가 설정된 빌드'는 사용자가 알 수 없는 말이다.
   - 고칠 문구:
     > 앱은 로그인 없이 사용할 수 있습니다. 입력한 도서 정보, 읽기 상태, 별점·한 줄 감상·긴 감상, 독서 회차·시간·쪽수, 갈피 문장과 메모, 책장 배치, 설정, 사용자가 찍거나 고른 표지·페이지 사진과 장정 이미지를 기기 안 앱 저장공간에 보관합니다. 이 정보는 책장 구성, 독서 기록과 갈피 표시, 타이머 복구, 백업·복원에 사용합니다.
     > 서버 동기화를 제공하는 버전은 처음 연결할 때 기기 전용 계정을 만들고 독서 기록·책장 배치·사진을 Covebook 서버(https://covebook.kodeploy.com)에 자동 동기화합니다. 동기화를 제공하지 않는 버전은 모든 기록을 기기에만 저장합니다. 어느 쪽인지는 앱의 '내 정보 › 백업 및 복원 › 동기화'에서 '이 기기에만 저장돼요' 또는 동기화 상태로 확인할 수 있습니다. 앱 제거만으로 서버 사본이 삭제되지는 않습니다.

2. **'도서 검색과 외부 연결' 문단**
   - 지금: '도서 검색을 실행하면 검색어를 Google Books로 보냅니다. 결과가 없거나 요청이 실패하면 Open Library로 보낼 수 있습니다.'
   - 문제: 실제 순서와 반대다(앱 시트와도 다르다). 책장 한켠 서버·YES24가 빠졌다.
   - 고칠 문구:
     > 도서 검색을 실행하면 검색어를 Covebook 서버로 보내고, 서버가 YES24 도서 정보에서 결과를 찾습니다. 서버에 닿지 않거나 결과가 없으면 검색어를 Google Books로 바로 보내고, 그래도 결과가 없으면 Open Library로 보냅니다. '인기 많은 책' 목록도 Covebook 서버에서 받습니다. Google Books·Open Library 결과에서 도서를 고르면 해당 서비스에 그 도서의 상세 정보를 요청합니다. 표지를 표시하려고 YES24·Open Library가 제공한 이미지 주소에 접속하며, 받은 표지는 기기의 임시 저장공간에 최대 90일 보관하고 백업 파일에는 넣지 않습니다. 이 과정에서 검색어, 도서·표지 식별자와 IP 주소 등 요청에 수반되는 통신 정보가 해당 서비스에 전달됩니다. 외부 서비스의 로그 보관·이용은 각 제공자의 개인정보처리방침에 따르며, 개발자는 제공자 로그를 직접 관리하거나 삭제할 수 없습니다. 직접 입력 기능을 이용하면 도서 검색 없이 책을 추가할 수 있습니다.
   - 링크: Google·Internet Archive 처리방침 링크는 그대로, YES24 이용 안내 링크를 더한다.

3. **'사진·카메라와 외부 AI' 문단**
   - 지금: '현재 버전의 AI 재장정, 사진을 통한 도서 식별, OCR 연결은 비활성화되어 있으며…'
   - 문제: 갈피 사진의 글자 인식(OCR)은 이미 동작한다(기기 안에서).
   - 고칠 문구(제목도 '사진·카메라'로):
     > 사진 선택과 카메라는 사용자가 표지나 갈피 페이지 사진을 추가하거나 바코드로 책을 찾을 때 사용합니다. 사진은 앱 내 저장공간에 복사됩니다. 갈피 사진의 글자 인식과 바코드 읽기는 기기 안(Android ML Kit, iOS Vision)에서 처리하며, 이를 위해 사진을 외부로 전송하지 않습니다. AI 재장정과 사진을 통한 도서 식별 기능은 제공하지 않습니다. 서버 동기화를 제공하는 버전에서는 동기화를 위해 사진이 Covebook 서버에 저장됩니다. 사진은 읽었다는 인증에 사용하지 않습니다.

4. **백업 파일(새 문단 또는 기존 문단 고침)**
   - 지금(앱 시트 예전 문구): '내보낸 백업 파일은 직접 고른 곳에 저장되며'
   - 문제: Android '다운로드 폴더에 백업 파일 저장'은 고르지 않고 다운로드/책장한켠에 바로 저장한다.
   - 고칠 문구:
     > 백업 파일은 사용자가 만들 때만 생성됩니다. Android에서는 기기의 다운로드/책장한켠 폴더에 바로 저장하거나, 공유 창에서 고른 앱(드라이브·메신저 등)으로 보낼 수 있습니다. iOS에서는 공유 창에서 고른 곳으로 보냅니다. 백업 파일에는 위의 기록과 사용자가 찍거나 고른 사진이 들어 있으며, 검색으로 받은 책 표지는 들어 있지 않습니다(복원 후 인터넷에서 다시 받습니다). 백업 파일을 보관·전달한 곳의 관리는 사용자에게 있으므로 다른 사람과 공유할 때 주의해 주세요.

5. **공개 범위(새 문단)**
   - 문제: 공개되는 것이 있는지 웹·앱 모두 답이 없었다. 독서 끝 화면의 '개인 기록 저장'이 오히려 '공개 기록도 있나?'로 읽혔다.
   - 고칠 문구:
     > 별점, 한 줄 감상, 긴 감상, 갈피와 독서 기록은 공개되지 않습니다. 커뮤니티를 제공하는 버전에서는 사용자가 커뮤니티에 직접 올린 글과 그때 고른 항목(책 제목·인용 문장·독서 시간 등)만 공개되며, 같은 책의 공개 평가를 보여 주기 위해 그 책의 ISBN을 Covebook 서버에 요청합니다.

6. **계정 삭제**
   - 동기화를 제공하는 버전에서만 해당한다고 문단 첫머리에 밝힌다: '서버 동기화를 제공하는 버전에서 서버 계정 삭제를 요청하면 연결된 로그인과 서버의 기록·사진을 삭제 처리하며, 기기 안의 기록은 남습니다.'

7. **최종 수정 줄**
   - '최종 수정: 2026년 11월 ○일 — 도서 검색 경로, 기기 안 글자 인식, 백업 파일 저장 위치, 공개 범위를 실제 동작에 맞게 고쳤습니다.'

## 앱 시트(고친 문구, 참고)

서버 없는 빌드(Android) 기준:

1. 책장 한켠은 로그인 없이 써요. 책·독서 기록·갈피·감상·사진은 이 기기 안에만 저장돼요.
2. 책을 찾으면 검색어가 책장 한켠 서버를 거쳐 YES24로 전송돼요. 서버에 닿지 않거나 결과가 없으면 Google Books로, 그래도 없으면 Open Library로 바로 전송돼요. 인기 많은 책 목록도 책장 한켠 서버에서 받아요. 검색과 표지 그림을 받을 때 IP 주소 같은 통신 정보가 함께 전달돼요.
3. 사진은 표지를 넣거나 갈피 원문을 보관하는 데만 쓰고, 읽었다는 인증에는 쓰지 않아요. 갈피 사진의 글자 인식과 바코드 읽기는 기기 안에서 하고, 그 사진을 밖으로 보내지 않아요.
4. 백업 파일은 직접 만들 때만 생겨요. 다운로드/책장한켠 폴더에 바로 저장하거나, 공유로 고른 앱(드라이브·메신저 등)으로 보내요. 그 파일에는 위 기록과 직접 찍거나 고른 사진이 들어 있어요(검색으로 넣은 책 표지는 빠져요).
5. 공개되는 기록은 없어요. 별점·한 줄 감상·감상·갈피는 나만 봐요.

서버를 쓰는 빌드에서는 1·3에 동기화 문장을 더하고, 5는 커뮤니티가 열렸을 때 '내 기록은 공개되지 않아요. 커뮤니티에 직접 올린 글과 고른 항목만 공개돼요.'로 바꾸며, 맨 끝에 서버 계정 삭제 문단을 둔다.
